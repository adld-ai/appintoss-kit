# Submission Metadata

When working on app submission, exposure information, store assets, or release
metadata, always report every Toss console input below. For each item, include
the proposed value, generated file path, or exact missing input needed from the
user. Keep all copy aligned with implemented app behavior; do not invent
unsupported features.

In `submission/inputs.md`, wrap every copy-paste text value in a markdown code
block so the user can click the copy button and paste directly into the console.
File paths and non-copy metadata stay as plain text or inline code. If a request
says `input.md`, treat it as the canonical `submission/inputs.md` file unless
the user explicitly names a different path.

When source screenshots, console pages, or developer docs show field limits,
placeholder text, helper copy, disabled states, or validation messages,
transcribe that information into `submission/inputs.md` exactly as observed. Do
not infer placeholder text that was not visible in the source material; write
`missing source screenshot` or the exact missing input needed from the user.

## Basic Information Fields

- Korean app name: required. The form shows a `10` character limit.
- English app name: required. The form shows a `15` character limit. Follow the
  console rule `단어의 첫 글자만 대문자로 작성해 주세요.` Capitalize only the
  first letter of each word. Use spaces to separate words; do not use camelCase.
- Subtitle: required. The form shows a `20` character limit. State the concrete
  user value, not a vague slogan. Use a friendly and empathetic `~해요` / `~아요`
  tone.
  - Good: `복용 시간을 놓치지 않게 기록해요`
  - Bad: `복용 시간 기록 관리`
- Detailed description: required. Explain what users see, which buttons/actions
  they use, and what outcome they get. Only describe implemented behavior. Split
  every sentence with a line break, one sentence per line.
- App ID / appName: required. Must match `granite.config.ts` and the console
  appName exactly. It may be disabled after app creation.
- User age rating: required. Use the value shown by the console if fixed.
- Customer support email: required. Use a real support email.

## Exposure Information Fields

- Category path: required. Report all three dropdown levels.
- App search keywords: required. Generated by the `app-seo-keywords` subagent.
  Report keywords one by one as a bullet list, not as a comma-separated line.
  Use terms users would type. Prefer concrete nouns and task words; avoid
  unsupported claims.
- App logo: required raster image, exactly `600 x 600px`.
- Dark-mode app logo: raster image, exactly `600 x 600px`.
- Thumbnail: required raster image, exactly `1932 x 828px`.
- Screenshots: upload portrait `636 x 1048px`, at least `3`, or landscape
  `1504 x 741px`, at least `1`.

## Version Memo

Version memo is required when uploading a new version in 앱 출시. Write every
entry as a `•` bullet list with a 2-space indent, one feature/change per line.
Do not use prose paragraphs, comma-separated lines, or markdown `-` bullets.
The total memo length, including `•`, spaces, and newlines, must stay within
`120` characters. In `submission/inputs.md`, place the Version Memo section
after the Exposure Info section.

```markdown
• 반찬 등록(카테고리, 만료일)
• 만료 임박 순 정렬
• 소비/폐기 체크
• D-Day 표시
```

For the console creation modal, copy fields must also be reported in
`submission/inputs.md`:

- 만들고 싶은 앱 설명
- 앱 이름
- appName
- 앱 유형
